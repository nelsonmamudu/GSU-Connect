# Phase 1: manual rollout gate

Repository changes only. Never run unattended migrations against production.

1. First take encrypted, access-controlled database and object backups outside Git; include auth/session tables, grants, policies, function definitions, bucket settings and an object manifest. Restore a copy on isolated infrastructure and validate it. A SQL backup does not back up file bytes. Never restore old refresh tokens to undo a suspension.
2. Compare the restored catalog to the migration, including triggers, RPC signatures, public views, storage grants, auth.sessions refresh-token cascade, and all effective API roles. Check for future definer functions not covered by the wrapper list. No service credential belongs in the app.
3. Exercise the application against this copy with synthetic accounts, two separate browsers and an Android device. Verify actual storage GET/signing, long-open voice/photo use, Realtime after suspension, pending upload/resume, sign-out-all and inability to refresh on another device. The in-memory SQL test is NOT a substitute. Validate signed-link residual lifetime. Auth-layer global logout does not erase downloaded files.
4. Release **only the enrollment-capable UI first**, with explicit approval. The owner opens Profile, sets up their authenticator and verifies a code. Keep the first session open. In a second clean browser, sign in, verify a fresh code and confirm AAL2 and TOTP AMR. Establish an offline recovery procedure before proceeding. Do not share a QR, secret or code with a reviewer/operator.
5. Report staging results, owner confirmation, backup/restore status, affected cohorts and rollout window. Obtain separate authorization for production. The operator sets the database session setting `gsu.verified_owner_id` to the independently identified owner's UUID for the migration connection. The migration aborts without the matching approved admin and verified TOTP factor. Do not disable the guard to pass CI.
6. Existing class reps have no trusted cohort by default. In the admin users panel confirm the rep's level from independent records, then confirm pending students' levels from proof/roster in the review panel. Until confirmed, reps see no such cases; helpers/admins can triage. Do not bulk-copy user-editable levels. Unsubmitted proofs stay out of the queue. Inform existing applicants to finish the upload.
7. Check ordinary access, non-member isolation and elevated actions immediately. On failure halt rollout; restore reviewed prior definitions from backup with privileged operator access, not a public bypass. Never undo a suspension by restoring session rows. Data retention, roster automation and account erasure are separate releases.
